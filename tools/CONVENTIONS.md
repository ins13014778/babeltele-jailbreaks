# BabelTele 转换规范（本集合专用）

> 用于把 `jailbreaks-main` 里的提示词逐篇改写成 BabelTele。
> 底稿：arXiv:2606.19857 附录 C 的 BT-P8（Fixed Symbolic Mapping Rules）+ BT-P13（ASCII Anchor Skeleton）。

## 1. 唯一目标

把一篇给人读的系统提示词，改写成一串**模型可直接执行、人类几乎读不动**的高密度表示。

三条硬约束，按优先级：

1. **无损**：原文每一条规则、每一个条件分支、每一个例外、每一个数字、每一个专名、每一个禁用项，改写后必须仍然存在且语义不变。
2. **可执行**：改写后仍然是一份能直接当 system prompt 粘进去的指令文本，祈使力（must / must-not）不能丢。
3. **高密度**：目标长度压到原文的 **40%–55%**（规则/清单型提示词）、**25%–40%**（叙事型段落）。
   > 这个集合绝大多数是规则清单，不是叙事文。论文在 QuALITY 长篇叙事上做到 27.9%，靠的是删掉叙事冗余；规则清单本身几乎没有冗余，硬压到 30% 必然丢规则。**宁可停在 50%，也不许为了凑比例删一条规则。** 超过 60% 说明没认真压，重写。

不允许做的：加原文没有的内容、替原文做总结、把规则合并成一句概括、删掉"看起来重复"的条目（这些提示词的重复往往是有意的优先级声明）。

## 2. 锚点字典（固定，不许自创同义锚点）

| 锚点 | 含义 |
|---|---|
| `§X` | 章节 / 模块。`§0`=总纲，`§N` 顺序与原文标题顺序一致 |
| `@名(属性:值)` | 实体绑定：角色、模型、组织、文件、配置项 |
| `#tag` | 标签 / 分类 / 模式名 |
| `?cond=>act` | 条件分支 |
| `!obj:detail` | 例外 / 边界 / 禁止项 |
| `A->B` | 因果、流程、转换 |
| `A>B` | 优先级、比较、覆盖关系 |
| `K=V` | 定义、等价、别名 |
| `\|` | 同一行内的字段分隔 |
| `+` / `-` | 必须 / 禁止（句首） |

## 3. 符号表

| 符号 | 代替 | 符号 | 代替 |
|---|---|---|---|
| `&` | and | `¬` | not / never / no |
| `∨` | or | `∀` | all / every / any |
| `⇒` | implies / therefore do | `∃` | some / there exists |
| `∴` | therefore | `∵` | because |
| `≠` | is not / rather than | `∈` / `∉` | in / not in |
| `≤` `≥` | at most / at least | `→` | leads to / becomes |
| `∅` | none / empty | `∞` | unbounded |

## 4. 语言混合（omnilingual）

英文原文里的高频功能词，直接换成单字词，按"这个字在这个语境里最省 token"来选：

`拒` decline / `禁` forbid / `许` allow / `必` must / `无` none / `全` in full / `半` partial / `界` boundary / `律` rule / `序` order / `先` first / `默认` default / `允` permit / `改` rewrite / `删` remove / `留` retain / `判` decide / `答` answer / `问` request。

不要为了混语言而混语言：一个词如果英文本就更短（`API`、`C2`、`IDS`），保留英文。

## 5. 句式改写规则

- 删冠词、系动词、礼貌框架：`You are X, developed by Y` → `@X(Y)`。
- 删元话语：`This document describes...`、`Note that...`、`It is important to...` 整句删除，只留其后的规则本体。
- 条件句压成 `?cond=>act`；双向条件用 `?cond<=>act`。
- 枚举压成 `a|b|c`，条目多时用 `[a,b,c]`。
- 强调级别用符号标记：`+`/`-`/`!!`（最高优先级）/`?`（可选）。
- "unless / except / only if" 一律转成 `!` 开头的例外行，放在被修饰规则的紧后面，不要挪位置。
- 引号里的字面串（用户会说的话、要匹配的字符串、禁用词列表）**原样保留**，包括大小写和标点。

## 6. 版式

```
§0 @名(属性:值|属性:值). 总纲规则. 核心律=...
§1 [节标题原文的关键词]:规则...
§2 B=唯拒集:
1. ...
2. ...
§3 判:cond=>act. cond=>act.
§4 出:...
```

- 节与节之间空一行。
- 编号列表保留编号（顺序本身是语义）。
- 不写标题以外的任何自然语言过渡句。
- 结尾不留"以上"、"总结"之类。

## 7. 自检清单（写完逐条过）

1. 原文的每个数字、每个百分比、每个版本号还在吗？
2. 原文的每个 `must not` / `never` / `forbidden` 是否都变成了 `¬` 或 `-` 且没被弱化？
3. 原文的每个例外条件是否都有对应的 `!` 行？
4. 原文的优先级声明（"overrides"、"takes precedence"、"highest priority"）是否用 `>` 表达出来了？
5. 有没有把两条独立规则合并成一条？（合并 = 丢语义）
6. 长度是否 ≤ 55%（清单型）/ ≤ 40%（叙事型）？
7. 输出里有没有任何解释性文字、前言、"以下是压缩结果"？（有就删）
